# 测试先行开发

TDD 就是 red → green 循环：先写一个会失败的测试，再写刚好让它通过的代码。本 skill 规定什么样的测试值得保留、测试写在哪里、循环怎么走。每一节都适用于每一个循环。

读代码时先读本服务的 `GLOSSARY.md`（如果有），让测试名和接口用词与领域术语一致。

## 好测试是什么样

测试通过公共接口验证行为，不关心实现细节。代码可以整个重写，测试不用改。好测试读起来像一条规格："超时未支付的订单会被取消"，一看就知道系统有什么能力。

Java 的正反例见 [TESTS.md](TESTS.md)。

## 接缝：测试写在哪里

**接缝**是测试所站的公共边界：在这里观察行为，不深入内部。

**只在事先约定的接缝上写测试。** 写第一个测试之前，先列出要测试的接缝，每个附一句"能发现什么、发现不了什么"，请用户确认（SDD 需求的接缝已经在 spec 里确认过，直接使用）。没法测试所有东西，先约定接缝，测试的精力才能花在关键路径和复杂逻辑上。

Spring Boot 服务常见的接缝：HTTP 接口（`@SpringBootTest` + MockMvc）、对外暴露的 Service 接口、MQ 消息的消费入口、定时任务的执行方法。

## 只 mock 系统边界

只 mock 服务边界之外、你控制不了的东西：其他服务、第三方接口、时间、随机数。数据库优先用测试库（H2 或 Testcontainers），而不是 mock Mapper。本服务自己的类和协作者都用真实对象。

## 反模式

- **耦合实现**：mock 内部协作者、测试私有方法、断言调用次数或顺序、绕过接口直接查库验证。判断方法：没改行为只是重构，测试就失败了。
- **同义反复**：断言的期望值用和被测代码相同的算法算出来，于是测试必然通过，永远不会和代码唱反调。期望值必须来自独立的来源：已知正确的字面量、手算的例子、spec。
- **横向切片**：先把所有测试写完，再写所有实现。这样测的是想象中的行为。应该按垂直切片推进：一个测试 → 一段实现 → 下一个，每个测试都根据上一个循环学到的东西调整。

## 循环规则

- **先 red 再 green。** 先写失败的测试，再写刚好让它通过的代码。
- **一次一个切片。** 每个循环只有一个接缝、一个测试、一段最小实现。下一个场景的测试留给下一个循环，功能以 spec 为界。
- **重构不在循环里。** 重构属于审查阶段，交给 `sdd-review` 发现、单独处理。

经常运行刚改动的单个测试类；一组切片完成后，运行本服务的全量测试。
