# 交接文档

把当前会话总结成一份交接文档，让一个全新的会话（可能是同事的、可能是另一个 AI 工具的）能够接着做下去。

## 什么时候用

交接的价值在于**可移植**：文档能带到别的地方去。适用于以下情况：

- 换 AI 工具，比如从 Claude Code 换到 Cursor
- 把工作转交给同事
- 换到另一个目录或仓库继续
- 做到一半发现一个旁支任务，想另开会话处理，不打断当前工作

如果只是同一个人在同一个工具里接着做，用工具自带的压缩功能（如 `/compact`）即可。

## 怎么写

- 用户给了参数时，把它当作"下一个会话要做什么"，围绕它组织内容。
- **不重复已经记录在别处的内容**：spec、design、tasks、ADR、需求单、commit、diff，直接引用路径或链接。
- 必须写清楚：
  - 目标：下一个会话要完成什么
  - 当前进度：做到了哪个任务、哪一步，哪些已经验证过
  - 已做出的决定，以及在会话里讨论过、但还没写进 spec 的结论
  - 未解决的问题和已知的坑
  - 下一步：具体从哪里开始
  - 建议使用的 skill：例如"继续实现 order-service T4，运行 `/sdd-implement order-service T4`"
- **脱敏**：去掉密钥、密码、token、个人身份信息。

## 保存位置

保存到操作系统的临时目录（`$TMPDIR`，没有时用 `/tmp`；Windows 用 `%TEMP%`），不放进工作空间，避免误提交。文件名用 `handoff-<需求单号或主题>.md`。

告诉用户文件路径，以及在新会话里怎么用它，例如"读 `<路径>`，然后按里面的下一步继续"。
