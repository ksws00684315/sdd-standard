# 多轮决策树提问

持续追问用户，直到双方对方案达成完整的共识。

## 决策树和 frontier

把要讨论的事看成一棵**决策树**：每个决策下面挂着依赖它的后续决策。

**frontier** 是所有"前置决策都已确定、现在就能回答"的问题。

## 按轮次提问

- 每一轮把 frontier 上的问题一次问完。依赖本轮其他问题答案的，留到下一轮。
- 每个问题编号，并给出推荐答案。措辞要让用户回答"是"就等于接受推荐。
- 等用户回答完再进入下一轮。已确定的决策会让 frontier 向外推进，解锁依赖它们的问题；每轮都重新计算 frontier。

每轮的格式：

```
❓ **Q1 - <问题标题>**：<问题内容，可以有多段，可以列出选项>

➡️ 推荐：<推荐答案和一句理由>

---

❓ **Q2 - <问题标题>**：...
```

## 事实归你，决策归用户

- **事实由你自己查**：代码怎么写的、配置是什么、表结构如何、现有文档怎么说，都自己去读，不拿去问用户。工具支持子代理时，可以派一个全新上下文的子代理去查；查询进行期间，只有依赖这个事实的问题需要等待，其余问题照常提问。
- **决策交给用户**：业务规则、取舍、范围，逐一提问，等用户回答。

## 结束

frontier 为空时结束：决策树的每个分支都已走过，没有留下任何默认假设。总结达成的共识，等用户确认后，才能据此采取行动。
