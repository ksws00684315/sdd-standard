# 10000 订单超时未支付自动取消（order-service）

- 需求单：<示例，无链接>
- 档位：L4
- 目标版本：6.11.1
- FEAT：FEAT-001（超时自动取消）、FEAT-002（取消后释放库存，本服务为调用侧）
- 涉及服务：order-service、inventory-service；全局 spec 见 `governance:10000-order-timeout-cancel`
- 需求负责人：@zhangsan
- 状态：已确认（记录在治理仓全局 spec）

## 背景

用户下单时会锁定库存，但部分订单一直不支付，锁定的库存不能卖给其他用户，热门商品经常被误显示为缺货。

## 范围

- 订单创建后超过超时时长（默认 30 分钟）仍未支付的，自动取消。
- 订单因超时被取消后，登记库存释放待办，由后台任务调用库存服务释放。

## 不做

- 不给用户发送订单取消通知（另提需求）。
- 不改变用户主动取消订单的现有流程。
- 不处理"已发起支付、未收到回调"的订单，这类订单由现有的支付对账任务处理。
- 不支持按商品或按用户单独设置超时时长。

## 需求与验收条件

<!-- 新增条目接续 `docs/specs/order-lifecycle.md`（SPEC-ORDER-001）的既有编号。 -->

- **FR-005**（FEAT-001）WHEN 订单处于"待支付"状态，且创建时间超过超时时长，THE SYSTEM SHALL 在 1 分钟内把订单改为"已取消"，取消原因记为"超时未支付"。
- **FR-006**（FEAT-001）IF 准备取消时订单已经处于"支付中"或"已支付"，THE SYSTEM SHALL 放弃取消，并记录一条告警日志。
- **FR-007**（FEAT-002）IF 库存释放失败，THE SYSTEM SHALL 保持订单为"已取消"，按退避间隔重试释放；连续失败 5 次后停止重试并告警。

## 非功能要求

- 扫描每分钟执行一次，单次最多处理 1000 个订单；扫描查询耗时小于 100ms。
- 多实例部署时，同一订单只会被一个实例取消。
- 超时时长和扫描开关可以通过配置修改，修改后无需重启。
