# 10000 订单超时未支付自动取消

- 需求单：<示例，无链接>
- 档位：L2
- 目标版本：6.11.1
- 涉及服务：order-service（主）、inventory-service
- 需求负责人：@zhangsan
- 状态：已确认

## 背景

用户下单时会锁定库存，但部分订单一直不支付，锁定的库存不能卖给其他用户，热门商品经常被误显示为缺货。

## 范围

- 订单创建后超过超时时长（默认 30 分钟）仍未支付的，自动取消。
- 订单因超时被取消后，释放它锁定的库存。

## 不做

- 不给用户发送订单取消通知（另提需求）。
- 不改变用户主动取消订单的现有流程。
- 不处理"已发起支付、未收到回调"的订单，这类订单由现有的支付对账任务处理。
- 不支持按商品或按用户单独设置超时时长。

## 需求与验收条件

- **R1** WHEN 订单处于"待支付"状态，且创建时间超过超时时长，THE SYSTEM SHALL 在 1 分钟内把订单改为"已取消"，取消原因记为"超时未支付"。
- **R2** WHEN 订单因超时被取消，THE SYSTEM SHALL 释放该订单锁定的全部库存。
- **R3** IF 准备取消时订单已经处于"支付中"或"已支付"，THE SYSTEM SHALL 放弃取消，并记录一条告警日志。
- **R4** IF 同一订单的库存释放请求重复到达，THE SYSTEM SHALL 只释放一次。
- **R5** IF 库存释放失败，THE SYSTEM SHALL 保持订单为"已取消"，按退避间隔重试释放；连续失败 5 次后停止重试并告警。

## 非功能要求

- 扫描每分钟执行一次，单次最多处理 1000 个订单；扫描查询耗时小于 100ms。
- 多实例部署时，同一订单只会被一个实例取消。
- 超时时长和扫描开关可以通过配置修改，修改后无需重启。
