# 订单状态流转

## 概述

订单从创建到完成或取消的状态变化规则。订单状态有：待支付、支付中、已支付、已完成、已取消。

## 业务规则

- WHEN 用户提交订单且库存锁定成功，THE SYSTEM SHALL 创建状态为"待支付"的订单。
- WHEN 用户对"待支付"订单发起支付，THE SYSTEM SHALL 把订单改为"支付中"。
- WHEN 收到支付成功回调，THE SYSTEM SHALL 把"支付中"的订单改为"已支付"。
- WHEN 用户主动取消"待支付"订单，THE SYSTEM SHALL 把订单改为"已取消"，取消原因记为"用户取消"，并释放锁定的库存。
- WHEN 订单处于"待支付"且创建时间超过超时时长（默认 30 分钟），THE SYSTEM SHALL 在 1 分钟内把订单改为"已取消"，取消原因记为"超时未支付"，并释放锁定的库存。
- IF 准备超时取消时订单已经处于"支付中"或"已支付"，THE SYSTEM SHALL 放弃取消，并记录告警日志。
- IF 超时取消后库存释放失败，THE SYSTEM SHALL 保持订单为"已取消"，按退避间隔重试释放；连续失败 5 次后停止重试并告警。
- 订单状态只能按上述规则变化；任何状态变更都只在订单当前状态符合预期时生效，多实例并发处理同一订单时只有一个生效。

## 相关数据

- `t_order`：订单主表。`status` 为订单状态，`cancel_reason` 为取消原因（用户取消 / 超时未支付）。
- `t_stock_release_todo`：库存释放待办。订单取消后登记一条，由后台任务调用库存服务完成释放；`retry_count` 为已重试次数。
