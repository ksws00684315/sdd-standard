# 跨服务需求的全局 spec 由治理仓承载

部分修订 [ADR-0001](0001-spec-in-service-repos.md)：模块 Spec 和各服务的变更 spec 仍放在服务仓库（该决策不变），跨服务需求由主服务承载改为由治理仓承载。

集团《SDD开发规范》（v1.0）第 9 章规定：同属一个研发云项目的多个仓库必须登记多仓模式，唯一合法拓扑是"治理仓 + 业务仓"的分布规格型；跨仓引用只能单向消费治理仓，业务仓之间不横向引用 spec。我们所有微服务同属一个研发云项目，此前"参与服务引用主服务仓里的 spec"不符合该拓扑。因此新建独立治理仓 `sdd-governance/`，承载 prd-index、FEAT 映射表、跨服务契约和跨服务需求的全局 spec 与 design；规则仓库不兼任治理仓，因为集团禁止治理仓存放通用模板，而那正是规则仓库的本体。代价是跨服务需求多了一层治理仓 MR 和 prd-index 登记，靠 `/sdd-grill` 自动生成条目对冲。
