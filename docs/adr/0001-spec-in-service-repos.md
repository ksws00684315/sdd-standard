# spec 放在服务仓库里，跨服务需求由主服务承载

我们的微服务各自是独立的 git 仓库。spec 有两种放法：集中放在规则仓库，或者分散放进各个服务仓库。我们决定把变更 spec 和现状规格都放进服务仓库，让 spec 和代码在同一个 MR 里评审、合并，生命周期和代码绑定。代价是跨服务需求的整体信息没有天然的存放位置，所以规定由一个主服务承载完整的 `spec.md` 和 `design.md`，参与服务只放本服务的 `tasks.md` 并链接主服务的 spec。规则仓库只放规则、术语表索引和跨服务 ADR，不放真实需求的 spec；`docs/example/` 里的示例 spec 只用于演示。
