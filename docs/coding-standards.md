# 团队编码规范

两轴审查中 Standards 方向的依据，也是代码评审的参考。服务特有的约定写在服务的 `AGENTS.md` 里，冲突时以服务的约定为准。

## 基础规范

以《阿里巴巴 Java 开发手册》（黄山版）为基础规范。下面各节只写团队在手册之外的补充，或者对手册条目的调整。

审查时按手册的条目等级处理：

| 手册等级 | 审查时的处理 |
|---|---|
| 能被 P3C 检查的条目 | 以 P3C 的检查结果为准，审查时不重复报 |
| 【强制】且 P3C 检查不了 | 按硬性违规处理 |
| 【推荐】【参考】 | 按需要判断的问题处理，给出建议，不阻塞 |

团队补充的条目，填写时遵守两点：

- **只写需要人来判断的规则。** 能用 P3C、checkstyle、编译器、单元测试检查的规则，交给工具，并在"已由工具保证"里注明，审查时就不会重复报。
- **每条规则写成可以判断的句子**，最好附一个正例，例如"Service 层方法对外抛出业务异常时，使用 `BizException` 并带错误码"。
